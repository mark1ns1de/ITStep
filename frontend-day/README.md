# Frontend Day — Bootstrap 5 + JavaScript

Навчальна адаптивна сторінка реєстрації на вигадану IT-зустріч. Реалізовано обидва обов’язкові завдання та додаткове завдання з категоріями й промокодом.

## Запуск

Відкрийте `index.html` у браузері. Інсталяція пакетів і сервер не потрібні. Bootstrap 5.3.8 збережено локально в `vendor/`, тому сторінка працює без інтернету.

## Функціональність

- **Реєстрація:** ім’я, email, кількість учасників; перевірка порожніх значень, формату email та додатної цілої кількості. Після перевірки — «Реєстрація успішна!» або пояснення помилки біля полів.
- **Калькулятор:** Standard — 400 грн, VIP — 800 грн. Для 1–2 квитків знижки немає, для 3–4 — 10%, від 5 — 20%.
- **Промокод:** `EVENT50` віднімає 50 грн після відсоткової знижки. Пробіли навколо та регістр не мають значення. Невідомий код показує попередження, але розрахунок без промокоду працює.
- **Деталі замовлення:** категорія, кількість × ціна, початкова вартість, відсоток і сума знижки, промокод та підсумок, що не може бути від’ємним.
- **Адаптивність і доступність:** Bootstrap-сітка, мобільна версія, підписи полів, керування клавіатурою, видимий фокус і повідомлення `aria-live`.

Це демонстрація: інформація не надсилається на сервер, реєстрації не зберігаються, листи не надсилаються, оплата не здійснюється. Поля кількості учасників і квитків незалежні: калькулятор дозволяє порівнювати варіанти перед заповненням форми.

Використано Bootstrap `container`, `row`, `col-lg-*`, `col-sm-*`, `form-control`, `btn`, `alert` та допоміжні класи. JavaScript-компоненти Bootstrap тут не потрібні, тому його JS-бандл не підключений.

## Як пояснити JavaScript

1. **Перевірка форми:** `validateRegistration()` у `script.js`. `trim()` прибирає пробіли по краях. `if / else if` перевіряють ім’я та email; `isValidQuantity()` перевіряє, що кількість — додатне ціле число. Обробник `registrationForm.addEventListener("submit", ...)` викликає функцію та показує результат. `event.preventDefault()` запобігає перезавантаженню.
2. **Змінні:** `const` використано для цін та значень, які не перепризначаються; `let` — для ціни вибраного квитка, відсотка, промознижки та підсумку, що залежать від умов. `Number()` перетворює значення числових полів із рядка на число.
3. **Розрахунок:** `calculateOrder()` множить кількість на ціну. Спочатку `if (quantity >= 5)` встановлює 20%; `else if (quantity >= 3 && quantity <= 4)` — 10%; `else` — 0%. Саме такий порядок не дає застосувати 10% до п’яти квитків.
4. **Арифметика:** `subtotal = quantity * ticketPrice`; `quantityDiscount = subtotal * (discountPercent / 100)`; `total = subtotal - quantityDiscount - promoDiscount`.
5. **Промокод:** `trim().toUpperCase()` нормалізує введення. Якщо код дорівнює `EVENT50`, віднімаємо 50 грн. Умова `if (total < 0)` встановлює підсумок у 0.
6. **Відображення:** `renderOrder()` заповнює підсумок через `textContent`. Після зміни полів попередній розрахунок ховається до повторного натискання «Розрахувати».

## Використання AI та Cursor AI

Цю версію згенеровано за допомогою **OpenAI Codex**: для завдання 1 створено розмітку, стилі й перевірку форми; для завдання 2 — калькулятор зі знижками; для завдання 3 — категорії та промокод. AI також допоміг підготувати пояснення й перевірки прикладів.

**Cursor AI у цьому сеансі не використовувався.** Якщо умовою здачі є саме Cursor, відкрийте проєкт у Cursor, попросіть пояснити `validateRegistration()` і `calculateOrder()`, самостійно перевірте приклади та допишіть сюди фактично виконані за допомогою Cursor дії. Не зазначайте роботу, якої не виконували.
